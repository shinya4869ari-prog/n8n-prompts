# 【韓国ニュース語学学習】n8n 自動巡回ワークフロー構築手順書（推し検索ON/OFF切替・本格詳報対応版）

## 📌 概要
本ワークフローは、毎日定期実行（毎朝7時等）または手動トリガーで以下を全自動で行います：
1. **実行設定の適用**（推し人物を検索するか・しないかを画面上のスイッチで切替）
2. **Supabase からお気に入り人物（推し）の取得**（`is_favorite = true` の人物）
3. **5大重要カテゴリ（犯罪/暮らし/政治/経済/外交）＋ 推し人物ニュースの一括RSS取得**（ON時: 計8カテゴリ / OFF時: 一般5カテゴリ）
4. **Google News RSS のXML解析とトップ記事抽出**
5. **Gemini Flash による 4段落（800〜1,200字）の本格報道記事再構成・段落対訳・語学抽出**
6. **Supabase の `news` テーブルへの安全 Upsert 保存**

## 🏗️ 全体フロー図（1本の直列パイプライン）

```text
[Manual / Schedule Trigger]
            │
            ▼
   [⚙️ 実行設定] ───────── (Edit Fieldsノード: include_celeb = true / false をポチッと選択)
            │
            ▼
[Supabase (お気に入り人物取得)] ── (GET: is_favorite=eq.true)
            │
            ▼
   [全カテゴリ統合コード] ─────── (5大カテゴリ ＋ 推し人物(ON時のみ) のクエリを生成)
            │
            ▼
   [Google News RSS取得] ────── (GET: {{ $json.rss_url }} でXMLを一括取得)
            │
            ▼
 [RSS解析・トップ記事抽出] ──── (XMLから各カテゴリのトップ記事タイトル・リンクを抽出)
            │
            ▼
 [Gemini 本格報道記事生成] ──── (Basic LLM Chain + Google Gemini Chat Model)
            │
            ▼
  [Supabase保存データ整形] ──── (記事情報とAI生成結果をマージ)
            │
            ▼
   [Supabase news Upsert] ───── (POST: newsテーブルに一括保存)
```

## 🎛️ 「推し記事を検索するか・しないか」の画面切り替え方法

n8nキャンバス上で、**コードを一切触らずに**切り替えられます。

1. **「⚙️ 実行設定」ノード** をダブルクリックして開きます。
2. `include_celeb` の項目を切り替えます：
   - **推しも検索したいとき**: `true`（トグルON）
     ➔ 一般5カテゴリ ＋ 推し人物（計6〜8件）を一括処理。
   - **推しは検索しないとき**: `false`（トグルOFF）
     ➔ 一般5カテゴリ（犯罪・暮らし・政治・経済・外交の5件のみ）を高速処理。
3. これだけで、後続の「全カテゴリ統合コード」が自動で設定を読み取り、実行件数を最適化します。
