# 🗄 キャスト・監督・アーティスト人物データベース（Personsテーブル）構築ガイド

映画・音楽の充実ワークフローで登録・更新された「監督」「キャスト」「歌手」「グループ・バンド」を自動的に自前データベース（`Persons` テーブル）として蓄積・一元管理するための設定マニュアルです。

---

## 1. Supabase でのテーブル作成 (SQL Editor)

Supabase の Dashboard ➔ **SQL Editor** を開き、以下の SQL を実行して `Persons` テーブル（およびグループ拡張カラム）を作成します：

```sql
-- 1. キャスト・監督・アーティスト 人物マスターテーブルの作成
CREATE TABLE IF NOT EXISTS public."Persons" (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL UNIQUE,          -- 日本語名 (例: ジャネル・セルガシナ, BLACKPINK) ※一意制約
    name_en text,                       -- 原語名・ハングル名 (例: Zhanel Sergazina, 블랙핑크, 지수)
    occupation text,                    -- 職種 (監督 / 俳優 / 歌手 / グループ)
    type text DEFAULT 'individual',     -- タイプ ('individual' 個人 / 'group' グループ)
    group_type text,                    -- グループ分類 (例: ガールズグループ, K-Pop)
    parent_group text,                  -- 所属グループ名 (例: BLACKPINK)
    members text,                       -- メンバー一覧 (例: ジス, ジェニー, ロゼ, リサ)
    profile_url text,                   -- 顔写真プロフィールの画像URL
    gender text,                        -- 性別 (female / male)
    country text,                       -- 出身国 / 制作国コード (例: KR, JP, US)
    wikidata_id text,                   -- Wikidata QID (例: Q25056960)
    created_at timestamp with time zone DEFAULT now()
);

-- 既存の Persons テーブルがある場合のカラム拡張 SQL（念のため実行）
ALTER TABLE public."Persons" ADD COLUMN IF NOT EXISTS type text DEFAULT 'individual';
ALTER TABLE public."Persons" ADD COLUMN IF NOT EXISTS group_type text;
ALTER TABLE public."Persons" ADD COLUMN IF NOT EXISTS parent_group text;
ALTER TABLE public."Persons" ADD COLUMN IF NOT EXISTS members text;

-- 2. 検索高速化のためのインデックスを作成
CREATE INDEX IF NOT EXISTS idx_persons_name ON public."Persons" USING btree (name);
CREATE INDEX IF NOT EXISTS idx_persons_name_en ON public."Persons" USING btree (name_en);
CREATE INDEX IF NOT EXISTS idx_persons_parent_group ON public."Persons" USING btree (parent_group);

-- 3. Row Level Security (RLS) の許可（公開読み込み＆サービスキー全権限）
ALTER TABLE public."Persons" ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access on Persons" 
ON public."Persons" FOR SELECT 
USING (true);

CREATE POLICY "Allow full access for service key on Persons" 
ON public."Persons" FOR ALL 
USING (true);
```

## 2. n8n ワークフローへのノード追加 (`Personsへ保存`)

- **Method**: `POST`
- **URL**: `https://uvjpiuinsgklddzhzpio.supabase.co/rest/v1/Persons?on_conflict=name`
- **Headers**:
  - `apikey`: `<YOUR_SUPABASE_ANON_KEY>`
  - `Authorization`: `Bearer <YOUR_SUPABASE_SERVICE_ROLE_KEY>`
  - `Prefer`: `resolution=merge-duplicates`
- **Send Body**: `ON`
- **Body Content Type**: `JSON`
- **Specify Body**: `Using JSON`
- **JSON**: `={{ $json }}`
