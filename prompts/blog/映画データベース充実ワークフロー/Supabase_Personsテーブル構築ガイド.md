# 🗄 キャスト・監督人物データベース（Personsテーブル）構築ガイド

映画データベース充実ワークフローで登録・更新された映画の「監督」および「キャスト」を自動的に自前データベース（`Persons` テーブル）として蓄積・一元管理するための設定マニュアルです。

---

## 1. Supabase でのテーブル作成 (SQL Editor)

Supabase の Dashboard ➔ **SQL Editor** を開き、以下の SQL を実行して `Persons` テーブルを作成します：

```sql
-- 1. キャスト・監督 人物マスターテーブルの作成
CREATE TABLE IF NOT EXISTS public."Persons" (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL UNIQUE,          -- 日本語名 (例: ジャネル・セルガシナ) ※一意制約
    name_en text,                       -- 英語/原語名 (例: Zhanel Sergazina)
    occupation text,                    -- 職種 (監督 / 俳優)
    profile_url text,                   -- 顔写真プロフィールの画像URL
    gender text,                        -- 性別 (male / female)
    country text,                       -- 出身国 / 制作国コード (例: KR, KZ)
    wikidata_id text,                   -- Wikidata QID (例: Q123456)
    created_at timestamp with time zone DEFAULT now()
);

-- 2. 検索高速化のためのインデックスを作成
CREATE INDEX IF NOT EXISTS idx_persons_name ON public."Persons" USING btree (name);
CREATE INDEX IF NOT EXISTS idx_persons_name_en ON public."Persons" USING btree (name_en);

-- 3. Row Level Security (RLS) の許可（公開読み込み＆サービスキー全権限）
ALTER TABLE public."Persons" ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access on Persons" 
ON public."Persons" FOR SELECT 
USING (true);

CREATE POLICY "Allow full access for service key on Persons" 
ON public."Persons" FOR ALL 
USING (true);
```

## 2. n8n ワークフローへのノード追加

映画充実ワークフローの末尾に以下の2つのノードを接続します：

### ① ノード名: `キャスト・監督抽出` (Codeノード)
- Mode: **Run Once for All Items**
- Code: [Persons_Supabase_Upsertコード.js](./Persons_Supabase_Upsertコード.js) のコードを貼り付け

### ② ノード名: `キャスト・人物保存ノード` (HTTP Requestノード)
- **Method**: `POST`
- **URL**: `https://uvjpiuinsgklddzhzpio.supabase.co/rest/v1/Persons?on_conflict=name`
- **Headers**: (※`Content-Type` は自動付与されるため不要です)
  - `apikey`: `<YOUR_SUPABASE_ANON_KEY>`
  - `Authorization`: `Bearer <YOUR_SUPABASE_SERVICE_ROLE_KEY>`
  - `Prefer`: `resolution=merge-duplicates`
- **Send Body**: `ON`
- **Body Content Type**: `JSON`
- **Specify Body**: `Using JSON`
- **JSON**: `={{ $json }}`

## 3. アプリ（`index.html`）での自前DB優先連携

自前DB（`Persons` テーブル）が構築されると、歴史館アプリ（`index.html`）で人物検索した際、Wikipedia や Wikidata などの遅い外部検索を待つことなく、自前の爆速高画質写真とカタカナプロフィールが優先表示されます！
